# 강사 진행 가이드

## 1. 이번 과정과 보관 자료

0·1번 자료는 그대로 사용합니다. 2~5번은 설정→요구사항→계획→구현·검증·커밋·PR 순서입니다. `tmp_`는 이전 강의·정의서·보완 명세의 원본 보관용입니다. 현재 과정의 근거는 [docs 안내](README.md)와 [실습 보완 명세](<실습 보완 명세.md>)를 따릅니다.

원문의 전체 서비스 범위는 Excel의 기존 시트에 보존되어 있습니다. 새 `Codex_실습범위`·`RAG_문서`·`RAG_API` 시트를 먼저 확인하고 기존 시트와의 관계를 설명합니다. 강의 전체 완성을 고객의 전체 요구사항 완성과 혼동하지 않습니다.

## 2. 학생 저장소 준비

강의 저장소 밖에 개인 실습 폴더를 만들고 docs·data·project를 함께 복사합니다. .venv·캐시·기존 .env·var DB는 복사하지 않고 1장 명령으로 환경과 DB를 준비합니다. 1장을 강의 저장소에서 이미 진행했다면 2장 전에 독립 폴더로 옮깁니다.

```text
healthy-day-codex-lab/   # 학생 Git 루트
├── docs/               # 요구사항·템플릿·테스트 자료
├── data/               # CSV 3개
└── project/            # 앱·실행 환경
```

최상위 폴더에서 Git 루트를 확인합니다. 상위의 다른 저장소로 인식되면 그 안에서 git init을 하지 말고 외부 폴더로 이동합니다. 저장소가 없는 것이 확인된 경우만 초기화합니다.

```powershell
# 최상위 위치와 기존 Git 저장소 유무를 확인합니다.
Get-Location
git rev-parse --show-toplevel
# 저장소가 없을 때만 main을 만들고 기준 자료를 커밋합니다.
git init -b main
git add -- docs data project
git diff --cached --stat
git diff --cached --check
git commit -m "chore: add healthy-day lab baseline"
```

project/.gitignore의 적용과 .env·DB·가상환경·캐시 제외를 확인합니다. 사용자 이름·이메일 미설정 오류는 학생의 Git 계정 설정으로 해결합니다. 학생의 개인정보·키를 강의 파일에 쓰지 않습니다.

## 3. GitHub 준비

GitHub 계정·실습 저장소 쓰기 권한·Actions 실행 가능 여부를 수업 전에 확인합니다. GitHub CLI가 없으면 설치하거나 PR 생성은 웹으로 진행합니다. 아래는 학생별 새 저장소를 만드는 예시이며 이미 origin이 있으면 실행하지 않습니다.

```powershell
# 학생의 GitHub 계정으로 인증합니다.
gh auth login
gh auth status
# Git 루트에서 이름·대상 계정을 확인한 뒤 새 저장소를 만듭니다.
gh repo create healthy-day-codex-lab --private --source . --remote origin --push
# 실제 대상과 기본 브랜치를 확인합니다.
git remote -v
gh repo view --json nameWithOwner,url,defaultBranchRef
```

이미 같은 이름이 있으면 새 이름을 선택하거나 해당 저장소를 clone합니다. 강의 저장소 remote를 학생 실습 remote로 그대로 사용하지 않습니다.

2~4장 준비 변경은 chore/codex-setup에 모읍니다. 5장 시작에 준비·CI를 main으로 fast-forward한 뒤 origin/main에 반영하고 feat/rag-chatbot을 만듭니다. 보호된 main은 준비 PR을 먼저 병합하고 main을 갱신한 후 진행합니다.

## 4. 외부 Skill 준비

Node.js·npm/npx와 네트워크를 확인합니다. [Skills CLI](https://github.com/vercel-labs/skills)의 현재 옵션, [find-skills](https://github.com/vercel-labs/skills/blob/main/skills/find-skills/SKILL.md), [grill-me](https://github.com/mattpocock/skills/blob/main/skills/productivity/grill-me/SKILL.md), [grilling](https://github.com/mattpocock/skills/blob/main/skills/productivity/grilling/SKILL.md)을 직접 읽습니다.

현재 grill-me는 grilling을 호출하는 진입점입니다. 둘 다 필요하며 원문이 바뀌면 의존성을 다시 확인합니다. Codex는 $로 선택·호출합니다. 다른 에이전트의 / 표기를 Codex의 내장 명령으로 설명하지 않습니다.

수업 리허설에서는 Skill을 실제로 설치하고 선택 목록·호출·인터뷰를 확인합니다. 확인한 버전/커밋, 설치 lock이 있으면 그 정보, 의존성, 설치 경로를 기록합니다. 자료에는 최신 원문 링크를 제공하며 설치·호출의 계정별 성공을 보장했다고 표시하지 않습니다.

네트워크가 안 되면 사전에 검수하고 라이선스를 확인한 로컬 Skill 폴더를 `npx skills add <로컬 경로> --agent codex --copy`로 설치할 수 있습니다. 단순 인터뷰 프롬프트만 사용한 경우에는 Skill 사용 완료와 구분해 기록합니다.

## 5. 공식 근거와 Groq 준비

수업 전 실제 상담용 공식 문서 1~3개와 질문 예시를 준비합니다. 문서명·기관·실제 URL·쪽번호/절·발췌·확인일을 사람이 대조하고 데이터 정의서의 문단 레코드로 구성합니다. 합성 fixture를 official로 바꿔 대신하지 않습니다.

자료는 학생의 project/data/reference/에 배치하며 이 강의 배포물에 공식 본문이 이미 포함되었다고 설명하지 않습니다. 배포·커밋이 허용되는 짧은 발췌와 출처만 포함하고 준비하지 못한 자료는 pending으로 둡니다.

Groq 키·계정에서 사용할 모델·호출 가능 네트워크를 확인합니다. 개발 도구 Codex의 모델과 서비스 Groq를 구분합니다. 기존 scripts.check_llm --live는 연결 점검이며 RAG 답변·인용의 검증은 구현 후 별도로 수행합니다.

자료·키가 없으면 모의 테스트·코드 PR은 진행할 수 있지만 실제 상담 검증은 미완료로 남깁니다. 학생에게 미실행을 숨기는 답변을 요구하지 않습니다.

## 7. 복구와 검증 범위

각 구현 단위 종료 시 커밋 해시를 기록합니다. 작업 복구는 현재 변경을 보관하고 검증된 커밋에서 별도 브랜치를 만드는 방식으로 진행합니다. git reset --hard나 DB 삭제로 실습 상태를 맞추지 않습니다.

시작 코드 테스트·실행 검증과 학생 생성 코드·실제 Skill/Groq/GitHub 성공을 구분합니다. 새 강의자료는 학생 구현을 위한 시나리오이며 학생별 외부 계정 리허설은 별도로 수행해야 합니다.
