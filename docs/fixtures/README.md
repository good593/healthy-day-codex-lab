# 합성 테스트 자료

`rag_test_corpus.json`은 실제 제품·건강정보가 아닌 가상의 서비스 안내입니다. 문단 검색·근거 부족·인용 오류·비신뢰 지시문을 API 키 없이 재현합니다. `example.invalid`는 테스트용 URL입니다.

documents에는 데이터 정의서의 필드를 가진 3개 문단이 있고 cases에는 11개 기대 결과가 있습니다. 테스트에서만 저장소·생성기를 주입하고 실제 상담용 자료 등록에서는 synthetic 레코드를 거부합니다. 여기의 verified는 테스트 문장 검수이며 공식 자료 검수와 다릅니다.

production_filter 사례는 source_type만 official로 바꿔 실제 자료 로더에 등록하려는 경우입니다. 파일의 synthetic 표시와 .invalid 출처는 그대로 남아 있으므로 로더가 거부해야 합니다. 이 검사는 모든 허위 출처를 자동으로 판별한다는 뜻이 아닙니다. 실제 자료는 사람이 원문을 대조합니다.

안내 태그가 매칭되는 질문은 A-1을 검색합니다. 무매칭은 생성기 호출 0회를 검사합니다. 매칭 문단이 질문을 뒷받침하지 못하면 모의 생성기가 부족 상태를 반환합니다. ID 검증과 답변 내용 대조를 각각 테스트합니다. 비신뢰 지시문 사례는 모델을 주입해 상태·비밀값 미노출을 검사하고, 실제 생성기에 전달되는 프롬프트에서도 근거와 지시를 분리하는지 검토합니다.

`intake_test_cases.json`은 이전 복용량 실습 자료로 보관하며 이번 과정에서는 사용하지 않습니다. 수정 전 자료는 tmp_ 접두사로 보관합니다.

모의 테스트 통과는 실제 Groq 연결이나 공식 원문 검수 완료와 구분해서 기록합니다.
